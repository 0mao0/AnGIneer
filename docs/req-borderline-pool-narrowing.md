# 需求：压线题池收窄专项（nightly 1040 题）

> 2026-09-27 立项讨论定稿方向。触发：nightly 总分逐晚稳定（±1pp），但题级每天 64~72 题翻转。
> 三层分解已结案（见下），生成非确定性是引擎特性、不可也无需根除——**可投资产的只有把边界题做扎实，翻转池自己会缩**。

## 1. 已钉死的证据（09-24 ~ 09-27，勿重复调查）

| 层 | 实测 | 结论 |
|---|---|---|
| 翻转规模 | 三对连续 run 翻转率 6.2~6.9%（64/72/70 题），净差 +4/−4/−26 | 单次整跑无分辨力，判定效应必须配对 |
| judge | 反转题中「答案逐字未变仍翻判」= **0/72、0/64、0/70** | 判分器贡献为零，不用动 |
| 检索 | top 集合 86~97% 逐位相同，Jaccard 0.96~0.98 | 检索侧稳定，不用动 |
| 生成 | temp=0、空闲、独占串行 10 发 = 10 个不同哈希（09-27 探针） | 非确定性在单请求计算路径内 |
| 源头 | dgx1（spark-4c47）vllm serve Qwen3.6-35B-A3B-NVFP4：`--enable-prefix-caching --enable-chunked-prefill --async-scheduling --quantization modelopt(NVFP4) --moe-backend marlin` + MTP 投机解码，TP=1 | 近 tie token 随 prefix-cache 命中/批切翻岔即整句换词，vLLM 设计特性 |

**已否决路径**（不要再提）：
- 评测侧串行——实测证伪（串行 10/10 全不同）。
- 动引擎参数求确定性——吞吐代价确定（prefix caching 关掉直接伤 TTFT）、收益未证。
- 换更严/更松 judge——judge 层贡献为零，动了只改水位不改方差。

## 2. 对象定义

**压线题池 ≈ 连续 run 翻转集的并集，当前约 70/1040（6.7%）。**
机制：这些题的判定落在判分阈值边界（对/错证据各半），生成端任何措辞扰动都会把它们推过线；
远离边界的题（无论对错）每晚答案怎么换词判都判得一致。

## 3. 阶段 1（本次要做的，成本半天，只出账不动手）

1. **拉并集题单**：取最近 3~4 个 nightly run 的逐题 correct 位图（evals.sqlite `eval_run_detail`，
   只读 URI），任一对翻转即入池；产出 `qid` 列表 + 每题翻转次数（0~N 对）分布。
2. **逐题分桶**（每桶的动作完全不同，混着看没有意义）：
   | 桶 | 判据（抽答案对+判词人工看） | 后续动作 |
   |---|---|---|
   | A 金标歧义/多解 | 两个不同措辞的答案都成立，金标只收一种 | 修题集金标/加同义表述 → 出数据集新版本 |
   | B 题干歧义 | 问题本身可两种读法 | 修题干表述，同上 |
   | C 真·贴边 | 金标无争议，答案确实时对时错（检索/答题在阈值边缘） | 才进"能力"账，按题型归到表格/图片/拒答等既有专项 |
   | D 判词贴边 | 答案质量稳定，judge 给分在判线附近摆动 | 记录，不动 judge 本体 |
3. **产出**：分桶题单 + 各桶占比。A+B 占比决定这个专项天花板——若 A+B 过半，主要工作就是修题集，一周内可收。

## 4. 成功判据（预注册，阶段 1 出数后允许修订一次并留痕）

- 主指标：**配对翻转池规模**——专项后连续两晚翻转数较 64~72 的地板下移；A/B 桶修完后 C+D 残余 ≤2% 记收口。
- 禁止口径：单晚总分涨跌当效应（噪声地板 ±1pp）；跨版本比绝对分不比配对。

## 5. 边界与红线

- 不改判分引擎、不动 judge prompt、不动引擎参数与部署形态。
- 题集修订 = 新版本号发布，**不原地改现役题集**（否则 nightly 历史与钉基线口径断裂）；
  换版后前几晚翻转数升高是预期（口径切换），单独标注不与专项成效混算。
- 数据取法纪律：ssh 走原生 OpenSSH；sqlite 只读 URI；探针法优先于整跑（便宜三个量级）。
