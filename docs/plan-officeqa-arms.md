## 4. 判据（跑前写死，事后不改）

- **主指标** = 133 题 0% 容差通过率。
  - **≥40% 好**：筛库收益抵掉无联网损失，逼近官方 3 月全库档（48.1）；
  - **30–40% 过线**：合理带——无联网结构性白丢约 13pp（D1）对上筛库检索空间缩小的反向收益；
  - **<30% 差**：先归因再定罪——拆 hit@5(doc)（检索没找到）vs 检索命中仍答错（解析/计算断），两类修法不同，不许笼统说"管线差"。

- **检索参照**（非门禁）：hit@5(doc)（gold 册在 `source_files` 内）随场报告，供 <30% 档归因用。
- **拒答观测**：`Unable to determine` 题单列（官方判 0，我们同样计 wrong，不单设拒答率判据——官方榜也没这维度）。

## 7. 结果（跑完回填）

### 7.1 试点 8 题双册（2026-10-07 08:37–08:57 北京时间，8 个单题 run 串行）

- **选法偏离 §6.6**：预注册写「试点 10 题」未钉选法；实跑 8 题 = **全部双册题（gold_doc_ids=2）的前 8 题**（UID0004/0005/0025/0065/0068/0073/0077/0094，取自 66 题双册族）。理由：双册=跨册捞针压力面，且一次同时验检索/问答/判分三段管道；单册题留给正跑 133。
- **健康红线（§4）：SCORER_ERROR=0、NO_GOLD=0 → 不触发作废线**。
- **检索参照**：hit@5(doc) **8/8 = 1.0**，failure_bucket 全 ok——**检索段健康**，金标册全部召回（含双册 2/2 全中）。
- **正误结果**：8/8 全 wrong，numeric_status 全 SHAPE_FAIL。逐题对账后定性：**不是检索问题、多数不是「答错」**——
  - UID0004 模型给出 1500.00%（金标 1499.39%，相对差 0.04%>0% 容差判错，且答案带多行外壳）；
  - UID0025 模型答 489（金标 142，检索全对但读数/计算错）；
  - UID0077/0073 证据在场但模型自称「没有检索到足够证据」= 证据上桌/组装层漏证据（与 10-04 上下文预算超限同族），非检索缺失；
  - UID0065/0068 数值正确（1.8、56）但多行外壳 + 尾行反问句致 SHAPE_FAIL；
  - 一次重试变体（run-c48aa0705a91 等）出现「空答→EMPTY」。
- **口径事实（回填时补记）**：§3.1 的「首跑 123 题、multi_doc 66/133」是**首轮转换缺陷**——官方 Pro 的 source_files 用 CRLF 换行分隔，只按 `;` 切会把跨册题合成单册假 stem；当前 bundle 与 DB 均为修复后版本（39 题 2-gold + 4 题 3-gold = 43 题多册）。引用 123 时必须注明是废数。
- **判分器处置决定（2026-10-07 业主确认）**：`NumericEvaluator.evaluate` 保留**「提取后判定」结构**（先提取答案候选、再过官方 shape 闸 + fuzzy 匹配），不逐字照抄官方 `score_answer` 全文直判：
  - 依据①：官方 harness 同构——先 `<FINAL_ANSWER>` 提取、后形态闸；
  - 依据②：全文直判会因「模型答案自带推理外壳」系统性误杀（试点 2 题数值全对被埋没）；
  - 依据③：提取器曾把「无答案证据」态（「没有检索到足够证据…」，2/8）误转成 WRONG，与官方 0 分口径冲突——提取器已收敛为「只剥外壳、不搬数字」并默认关闭（env `ANGINEER_NUMERIC_TAIL_LINE=1` 才启用），默认 = 官方全文直判口径，重放 12 条真实答案 0/12 假绿。
  - 对外引用纪律不变：引用时注明「提取器自研，官方 harness 同构但非逐字」。

### 7.4 正跑 133 结果（run-e41d528588ac，2026-10-07 10:52–11:44 北京时间，dev 机 HTTP 触发）

- **主指标（§4）：0% 容差通过率 = 0/133 = 0.0%** → 落「<30% 差」档，按 §4 要求先归因再定罪（下）。
- **健康红线（§4）：SCORER_ERROR=0、NO_GOLD=0**（133 题逐题核实）→ 本场有效，不作废。
- **检索参照**：hit@5(doc) = 125/133 = **93.98%**；按金标册数分层：1 册 63/67、2 册 36/39、3 册 13/13、4 册 9/10、5 册 3/3、7 册 1/1——**多册题不比单册差，检索段达标**。
- **失败分解（133 题全 wrong）**：
  - `SHAPE_FAIL` **115 题**（形态闸判 0）：其中「多行回答」100 题、「数字个数不符金标」15 题；
  - `EMPTY` **18 题**（真空答）：**全部为 L3「标准计算」路径**，trace 留痕 `上下文预算超阈值，停止继续调用工具（should_stop）` → `生成结束：本轮未产出首字（按边界规则收尾）`——工具循环撞预算闸后终答没产出。
  - 答案壳形态统计：38 题（28.6%）的答案是**拒答/守卫替换文本**（23 模型自拒 + 4 定稿拒答 + 8 无证据替换 + 3 引用不支持替换）；77 题为模型正常作答（但都不是单行直答形态）。
- **归因（§4 要求的二分）**：检索命中 125 题里 107 SHAPE_FAIL + 18 EMPTY；检索 miss 仅 8 题（6.0%）→ **主因不是「检索没找到」**；主因是①答案形态与官方直答闸（`_is_direct_answer_only` 只认单行）结构不兼容 + ②答案产出缺口（18 空答 + 38 拒答/替换）。
- **旁证档（非官方口径，离线回放存量答案、不重跑问答）**：尾行提取器 ON × 0% 容差 → **17 PASS = 12.8%**（+41 WRONG +57 仍 SHAPE_FAIL +18 EMPTY）；× 1% 容差 → 19 PASS = 14.3%。提取器只救形态不救内容（41 题提取出的尾行数值不等于金标）。
- **数值在场上界探针**：金标数值形态出现在答案文本中 24/133 = **18.0%**（上界，含推理过程数字的误撞）——即便完美剥离形态噪声，内容面正确率上限约 18%，**仍 <30%**。
- **耗时**：单题 p50 73.7s / p90 143.5s / max 587s；总 202.5 分钟 GPU 时间、4 并发挂钟 52 分钟（run manifest：默认模型 Qwen3.6-35B-A3B、workers=4、零判官调用）。
- **结论（内部定位不变）**：本场数字**不足以支撑任何对外成绩**（0% / 旁证 12.8%）；库内定位仍是「历史档案检索-解析压力集」。能力结论一句话：**检索段达标（94%），缺口集中在生成段——答案产出率（空答/拒答 56 题）与官方直答形态适配**；这两项修完前，数值正确率无从测量（上界 18%）。

### 7.7 注入实验（预注册 2026-10-07 立稿；用户指示新开独立会话实施，结果回填于此节）

**动因**：7.4 归因①——模型从未被告知「最终答案单行收尾」（QA v16 与 L3 复杂档提示词为聊天产品设计，要求出处/列表/讲解，无一字规定收尾形态）。本实验验证：评测侧注入一条「答案收尾形态」要求，能否把「会做但形态不合」的题翻成 PASS。同时是「问答编排注入口子」产品能力（客户自定义回答格式）的最小验证；口子对外产品化另立需求，不在本实验范围。

**注入语句（先原文预注册；执行会话落码前可复核措辞，改动须在此节留痕）**：

> 若问题是数值/计算类：正文照常给出依据与推理；最后必须另起一行，只写最终答案本身（数值带单位，不写解释、不加其它文字）。

**判据（跑前写死）**：
