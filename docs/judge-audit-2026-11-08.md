# 判官质量审计与边界双判（2026-11-08）

- 目的：量化生产判官（Qwen3.8-Flash-Next，语义判分段）的噪声与偏差，决定是否/如何修
- 状态：审计完成；边界双判已实现（开关默认关，随 v0.3.11 部署后经 .env 启用）

## 1. 审计方法

- 样本：FinanceBench 生产 run（run-1c2f9814）非拒答类 53 例（33 错 + 20 对抽样）；
- 两个口径：同判官（Qwen3.8）复跑复判 vs 存档判词（稳定性）；另一判官（Qwen3.6）复判
  vs 存档（独立性）；第三判官 SAGE 仲裁不可用（网关 502）；
- 判官 prompt 逐字复用生产 v5 语义评测模板（含 keyword_hint/gold 构建逻辑）。

## 2. 审计读数

| 指标 | 读数 |
|---|---|
| 同判官重跑与存档一致率 | **86.8%（46/53）**——13% 判词在完全相同输入上翻转（温度 0.1） |
| 独立判官（3.6）与存档一致率 | 86.8%（46/53） |
| 疑似冤案（存档错 → 3.6 判过 0.7-0.9） | 6 例（理由均写「核心结论一致，仅缺细节」） |
| 疑似漏判（存档对 → 3.6 判错） | 1 例 |
| 反事实·双采样中位（3.8 双采样） | **95.7% 与存档一致（45/47）**，只翻 2 例（1 修 1 伤） |
| 反事实·双判中位（3.8+3.6） | 90.4%（47/52），4 修 1 伤 |

结论：判官自翻转 13% 是系统性噪声源，影响所有读数（含 A/B 净差 −2 与夜测分数）；
「核心结论一致仅缺细节」被生产判官按 0.4-0.6 判错，违背其 prompt 自述宽容规则。

## 3. v6 提示词尝试（已回退，记录在案）

硬性分数带方案（核心结论命中强制 ≥0.7 + reason 声明档位）验收**不通过**：
FinanceBench 存错→过 3 例（预期内）但反向误伤 2 例数值近似题（0.83 vs 0.82 判缺失）；
OpenRAG 主集 30 例存档错题被翻过 18 例（60%）——判定「核心结论命中」被放宽成
「主题相关即命中」，属分数通胀而非校准。**已 revert，不采纳。**

## 4. 边界双判（采纳的实现）

- 复用既有双判一致制（`ANGINEER_JUDGE_REJUDGE=1`，judge_audit.py，10-14 建，默认关）；
- 新增**边界带**（`ANGINEER_JUDGE_REJUDGE_BAND`，默认 `0.4,0.7`）：首票不在模糊带内
  直接收口；带内才加判第二票，两票分歧加第三票多数——成本从 2× 压到约 1.1×；
- 空字符串=无带=全量双判（向后兼容）；非法配置按无带处理（宁多判不漏判）；
- 留痕：`semantic_rejudge{scores, votes, mode}` 随 scores 落库；
- 验收口径：上线后同 53 例复算一致率应 ≥ 95%（反事实已证 95.7%），且 openrag 不得
  出现批量翻过（>20%）。

  `docker compose up -d aichat-api` 重建后生效（env_file 固化，restart 无效）。
- 回滚：`.env` 删该行重建即回单判（代码向后兼容）。
