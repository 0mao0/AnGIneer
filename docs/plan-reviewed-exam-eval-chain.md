## 4. 剩余项（待开工）

优先级按「对跑通率的杠杆」排序。

### P2-1 表内行语义：复式表头子表头行被当数据行

- **现象**：实录类表（多行表头，如「散货/集装箱船船舶主要尺度实录表」）的**子表头行**
  被当作数据行匹配，`best_row` 落到子表头 → 返回值是列标签而非数值。
- **证据**：`表A.0.2-1~14` 选表修正后，返回 `{"序号": "序号", "载重吨DWT(t)": "载重吨DWT(t)", …}`。
- **落点**：`services/angineer-core/src/angineer_core/table_query_engine.py`（行匹配/表头识别）。
- **验收**：q2020-001 / q2020-006 的 T / b 取值出数；engine 单测新增复式表头用例。

### P2-2 列匹配：`dwt` 维度列跳过与真实列名冲突

- **现象**：`_find_column_index` 的维度列跳过名单含 `dwt`，会把表头「载重吨DWT(t)」
  （真正的吨级列）当维度标注列跳过 → 数值条件（吨级）解析不到列。
- **附随**：列名别名词典缺（「吨级」↔「载重吨DWT」↔「船舶吨级」）。
- **落点**：同 P2-1 文件的 `_find_column_index` + 领域包 `arg_rules`。
- **验收**：真实表上「吨级」条件能定位到「载重吨DWT(t)」列。

### P2-3 取值：`target_column` 失配时被「成对列」劫持

- **现象**：`target_column` 找不到列时，引擎落到「条件列相邻列」启发式（取的是**条件列**
  的下一列）→ 把 T 读成吨级列的值。
- **证据**：`query_tables(..., target_column="满载吃水T(m)")` 在样例表上返回 32.0（吨级值）。
- **落点**：同 P2-1 文件的 target-col 推断段。
- **验收**：单测断言失配时**不猜**（返回整行或明确 error），不静默给错列。

### P2-5 路由未命中的 SOP 覆盖（终轮实测 6 题）

- 题面判 L3 但**无匹配 SOP** 而空转：q2020-002（铁路调车轨枕）、q2020-020（码头供水水头）、
  q2020-017（栅栏板几何）、q2020-028（修船坞底高程）、q2020-056（重力式直立堤概念题）、
  q2019-007-1（船舶回旋圆尺度）。
- **对照类**（终轮 7 题）：命中 SOP 但**缺参**收场——q2020-001/007/004/006、q2019-008/006/009，
  即 P2-1~P2-3 与 P2-7/P2-8 的靶区（P2-4 已于 2026-10-15 完成，见 §3）。两类合计 13/50，
  是 SOP 链当前的主要失分面。
- 两条路：补 SOP 定义，或按题集标注归位（**后者动数据，改前需业主确认**）。

### P2-6 选择题误判 L3 的题型识别

- 「下列关于…叙述，符合规范规定的是」型选择题被误判 L3 送进计算路数空转
  （其本身是 L1/L2 知识题）。属分类器题型识别，小改动。

### P2-7 读表判读：区间列的「标签与取值」错配（P2-4 验收新发现）

- **现象**：读表判读通道（`canonical_table_read`，走 LLM 取值）在**区间列表头**上会
  认对列标签却给出邻列的值。
- **证据**：q2020-007 的 step_5（表6.4.6-1，Z1）：返回 `cell="坚硬粘性土…×
  100000≤DWT<300000"` 但值 **0.60**（该列应为 0.70；`quote` 里整行 5 个值都抄了）。
  连带 D0=19.75（应 19.85）→ 该题最终选项错位。
- **落点**：读表判读提示词（`canonical_table_lookup.canonical_table_read`）——需加
  「表头为区间（a≤X<b）时取包含条件数值的列」约束。**提示词影响所有 SOP 的读表步，
  改前须预注册 A/B（同表对照 2 次读值即可）。**
- **验收**：q2020-007 的 Z1 读成 0.70；同表 5 列区间各抽 1 例不串列。

### P2-8 乘潮水位成对写法解析错位（P2-4 验收新发现）

- **现象**：领域包 `pick_ts_water` 算子的两条扫描正则都是「频率↔水位」同段就近配对，
  题面写成「累积频率85%、95%的水位分别为3.0m和2.6m」这种**双列并排**时，95% 被配上
  85% 的水位值。
- **证据**：q2019-008 得 `Hnav=3.0`（应 2.6，gold 取 95%）→ 最终 `航道设计底高程
  =−22.13`（gold −22.53，选项 D）。
- **落点**：`domain_arg_rules.py` 的 `pick_ts_water`（引擎侧，多个 SOP 共用 Hnav）——
  需按出现序把频率列与水位列**成对 zip**，属共享算子语义变更，须预注册 A/B 后改。
- **验收**：q2019-008 `Hnav=2.6`；对照组（单值写法「乘潮水位为X」）行为不变。
