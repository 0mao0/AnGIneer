# 用户端 AI 对话停靠列设计

日期：2026-08-10

状态：待用户审阅

## 1. 背景与目标

用户端（user-web）的 AI 对话目前是一个整页高度的右侧抽屉浮层（`a-drawer`），会盖住应用头部与页签区域，且与 PDF 预览高度不一致。

目标：把 AI 对话改为停靠在内容区右侧的固定列，与 PDF（以及其他页签内容）完全同高，不再悬浮遮挡整个页面；保留右下角按钮控制打开/收起。

## 2. 已确认的需求决策

| 决策点 | 结论 |
| --- | --- |
| 停靠形式 | 内容区右侧固定列，与内容区同高 |
| 显示范围 | 所有页签（文档、SOP、GIS、项目）都显示 |
| 打开方式 | 保留右下角悬浮按钮；打开后按钮隐藏，由对话列头部“关闭”按钮收起 |
| 对话状态 | 面板始终挂载（`v-show` 控制显隐），关闭再打开不丢对话 |
| 面板宽度 | 固定 440px（与现有抽屉一致），不做拖拽调宽 |
| 数据流 | AIChat 的会话 ID、传输通道、引用跳转逻辑全部留在 App.vue |

## 3. 组件边界与架构

### 3.1 Workbench.vue：新增可选右侧插槽

- 新增 `#right` 插槽；
- 内容区由“单一视图”改为“主视图 + 右侧列”的横向布局：
  - 主视图：`flex: 1; min-width: 0; overflow: hidden`；
  - 右侧列：固定 440px、左边分隔线、与内容区同高、内部纵向布局；
- 未提供 `#right` 插槽内容时，布局与现在完全一致（主视图占满）。

### 3.2 App.vue：抽屉改为停靠列

- 删除整页高度的 `a-drawer` 及其专属样式；
- 把 `AIChat` 放入 Workbench 的 `#right` 插槽，用 `v-show` 绑定 `aiChatVisible`；
- 对话列头部：左侧“AI 对话”标题，右侧“新建对话”按钮与“关闭”按钮；
- 右下角悬浮按钮在面板打开时隐藏（`v-if="!aiChatVisible"`），避免与面板重叠；
- 保留 `aiChatRef`、`chatSessionId`、`chatPanelPlaceholder`、引用跳转等现有逻辑。

### 3.3 AIChat 组件

- 不改 AIChat 组件内部实现；
- 继续通过 `title=""`、`show-context-info`、`scene`、`session-id`、`transport`、`@select-citation` 等现有 props/事件使用。

## 4. 数据流

无变化。会话状态、传输通道、引用跳转继续由 App.vue 持有；Workbench 只负责摆放位置，不感知对话逻辑。

## 5. 交互细节

- 面板打开：点击右下角悬浮按钮 → 右侧列出现，按钮隐藏；
- 面板收起：点击对话列头部“关闭”按钮 → 右侧列隐藏（内容保留），按钮重新出现；
- 新建对话：点击头部“新建对话”按钮，调用现有 `aiChatRef.value?.startNewChat?.()`；
- 所有页签切换时右侧列保持打开状态，高度始终与当前页签内容区一致；
- 无打开页签（空状态）时，对话列仍可正常显示和使用。

## 6. 错误处理与边界情况

- 面板隐藏时组件不卸载，避免丢失对话与滚动位置；
- 窗口/面板宽度变化时，对话列保持 440px，主视图自适应剩余空间；
- 若 AIChat 内部渲染异常，由现有 TabErrorBoundary / 组件自身容错处理，不新增错误路径。

## 7. 文件改动清单

| 文件 | 改动 |
| --- | --- |
| `apps/user-web/src/layouts/Workbench.vue` | 新增 `#right` 插槽与内容区横向布局样式 |
| `apps/user-web/src/App.vue` | 删除抽屉，改为 Workbench 右侧停靠列，调整悬浮按钮显隐 |

## 8. 验证与测试

1. 运行 `pnpm --filter @angineer/user-web build`，确认类型与构建通过；
2. 手工验证：
   - 文档页打开对话列后，与 PDF 同高；
   - 切换到 SOP / GIS / 项目页签，右侧列保持显示且与内容同高；
   - 关闭再打开，对话内容不丢失；
   - 面板打开时悬浮按钮隐藏，关闭后面板按钮重新出现；
   - 新建对话、引用跳转功能正常。

## 9. 明确不做

- 不做面板宽度拖拽调节与宽度持久化；
- 不修改 AIChat 组件内部；
- 不改变管理后台的 AI 对话布局。
