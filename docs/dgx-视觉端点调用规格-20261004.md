## 一、对方回复原文（2026-10-04）

① 图片 base64 后请求体上限 32MiB，原始文件请控制在 22MB 以内；无单图独立限制。
② 降采样按 token 数：每张图上限 = 4096÷图数（1 图≈1790×1790、4 图各≈905×905），保持纵横比、28 像素对齐，
   token 精确不超；页面图建议单图 ≤1.2MP、多图时按图数等比缩小；边长 ≤8192、像素 ≤16MP，超出直接 400。
③ 并发与文本同一 8 条 lane 池，无视觉配额差异，无需改并发策略。

## 三、对本项目调用端的约束（figure_describer 改指视觉档时按此实现）

- 单请求 ≤4 图；视觉 token 是全请求共享的 4096（图越多每图越小，8 图各约 512 token）。
- 页面图建议 ≤1.2MP（约 1095×1095 ≈ 1500 视觉 token，单图场景余量充足）；多图等比缩小。
- 客户端先缩图（保纵横比、28 像素对齐）再 base64：省带宽，也压单张耗时（现状大图单张 20–30s）。
- 硬红线（超出直接 400）：单边 >8192、单图 >16MP、请求体（含 base64）>32MiB。
- 并发无需额外设计（与文本共用 8 lane 池）。
- 遗留口径：`usage.prompt_tokens` 不含视觉 token（10-04 实测 184→189），计费/预算记账仍无读数——本规格只给容量上限。
