## 四、发现（三个真 bug + 两个效力限制）

### 1. ⚠️ 召回命中率是最大缺口（修前仅 4/22）——**这条直接改 M2 的设计**

首跑时 22 例里只有 **4 例**（A1/A2/A3/A4）能召回出子图段，其余 18 例段为空。
根因：BB §4 首版召回只做「规范号 / 条款号 / 序数」匹配，而真实追问大多是
「DWT=40000 的满载吃水」「沉箱干舷高度应满足哪条规范」这类**不带显式线索**的问法。

处理（已实现）：补 `token 匹配（拉丁词/长数字/中文词段，去停用词）+ 最近轮近邻兜底`，
命中率升到 **20/22 有段**。仍为空的 2 例：
- `C6`：单轮题（无历史）→ 图空，属预期；
- `D4`：**历史里没有一条被引用条款**（首轮回答无 `[Kx]` 标记）→ 图空。

⚠️ 这是**确定性兜底**，不是 BB §4 说的「二期向量召回」。M2 落地时必须在
「字符串版召回」之外显式评价这条兜底的效果——否则真实流量上会出现「图有内容但召回不中」
的静默退化（本报告最后一条给出的就是这种量级的证据：18/22 命中不了）。

### 2. 序数消解指向了空的「当前轮」（bug，已修）

`build_graph` 里 user 消息即开新 run，而本轮提问自己就开了一个新 run →
`runs[-1]` 是空的当前轮，`run_cites[-1] = []` → 「刚才第二条…」召回 0 节点。
修法：指向**最近一个产出过引用的已完成轮**（`cited_runs[-1]`）；另加「序号超出该轮引用条数
时回退取该轮全部」（同 doc+section 被引用两次会去重成一个节点，序号指名会落空）。

### 3. ⚠️ 图空时不许移除证据（护栏，已修）——**D4 实测命中**

臂 3 原实现无条件丢弃历史 tool 消息。D4 的历史里没有任何被引用条款（图空、段为空），
于是 prompt 从 **13,248 est 掉到 164 est** —— 证据被丢掉、又没有任何东西补上，
等价于裸答。修法：**段为空则完全不丢弃**（退化为臂 1 行为）。D4 现为 13,248 est（与臂 1 同）。
> 这条是预注册层面的修正：arms §1 的臂 3 定义必须写死「图上无可用节点 → 不移除证据」。

### 4. 题集两处引号与库不一致（保真测试抓到）

`C2`「乘潮累积频率」、`C3`「设计使用年限」在库里用的是**全角弯引号 `“ ”`**，
题集与 arms §3 表里写的是角括号 `「 」`。保真测试（`(session_id, seq)` 处逐字比对）当场报红，
已按库内原文改正（题集与 arms 同步）。**预注册件里的引号必须与库一致**，否则复现口径不成立。

### 5. 效力限制：5/22 题在 QA 档 16k 预算下根本不触发压缩 → 臂 1 ≡ 臂 2

`B1 / B2 / C6 / D2 / D4` 的历史段总量都在 16k est 以内（14,400 / 14,562 / 7 / 14,616 / 13,248），
压缩器不触发 → **臂 2 与臂 1 逐字相同**（总 est 完全一致）。这 5 题对「指针是否有效」零信息量：
- 若判分跑仍用 16k，**M0 的有效样本是 17 题**，不是 22；
- 若想让这 5 题也进有效样本，需对它们另设更小预算重跑——**属预注册口径变更，需业主裁决**（见 arms §7）。

### 6. 记录项

- 闸 B 上限偏松：实测子图段 max 270 est（上限 2,000），M2 可考虑收到 500-800 est。
- 臂 2 的指针开销有界但非零：单题 max +989 est；若 M2 之后图段也要进 prompt，
  两段预算需一起算（当前设计把它们当两笔独立开销）。
