## 目的与三臂定义

nightly v4（1040 题）只有全链一个数字，缺参照系。三臂同题、同语料、同判分引擎：

| 臂 | 配置 | 回答的问题 | 状态 |
|---|---|---|---|
| 臂 1 全链 | 五路召回 + 融合重排 + 结构化 + 拒答守卫 | — | ✅ 84.9%（2026-09-24 基线） |
| **臂 2 朴素 RAG** | 通用配方（本文件第二节），砍掉全部自研工程 | 工程层值几个点 | 本文预注册 |

## 指标与预注册判据

| 指标 | 臂 2 读法 | 对照（臂 1） |
|---|---|---|

**判据（跑前写死，跑后不回改解释）**：

- 可答题正确率差 **≥ 3pp** → 工程层增益成立，可作销售数字（「同题同库同判分，比通用配方高 X 个点」）；
- 差 **< 3pp** → 增益不显著，卖点转向「私有语料可控、引用可溯源、拒答守卫、工程域定制」，不宣称正确率领先；
- hit@5 差 ≥ 6.5pp（96.5 − 90）→ 检索层是增益主导；臂 2 hit@5 ≥ 93.5% → 检索层增益有限，增益主要在生成/守卫层；
- 39 题硬答率 > 80% → 「拒答守卫防跨文档幻觉」单独立为差异化卖点。

## 公平性纪律

1. 配方参数不做逐题调优；**100 题试点只看管道健康**（报错率、hit@5 水位、答案目检），不据此改配方；
2. 臂 2 喂的是原始 PDF 抽取文本，臂 1 吃的是我们解析管线产物——这个差异是**被测变量本身**（解析质量也是工程的一部分），如实呈现不遮掩；
3. 判分失败题按 nightly 同规则兜底（关键词断言），不人工改判；
4. 结果无论好坏都发布到本文件的结果段——**选择性报告 = 全部作废**。

## 臂 3 预注册（2026-09-27 追加，跑前写死）

**目的**：回答「把原文 PDF 直接给大模型，还要不要 RAG」——对销售与产品方向都最锋利的一问。

**两阶段口径（本文件同时声明两次跑的定位，避免结论混用）**：

| 阶段 | 模型 | 定位 |
|---|---|---|
| 阶段 1（本次，2026-09-27） | 网关注册的 **Qwen3.8-Flash-Next**（`/api/llm2`） | **只作内部水位 + 每题 token 计量**；非顶级模型，结论**不得对外声称** |
| 阶段 2（待用户提供顶级 key） | 顶级长上下文模型（Gemini 2.5 Pro 首选） | 正式臂 3，对外结论以此次为准 |

**配方（两阶段一致，仅换模型）**：
- 输入 = qrels 指定的该题 gold 论文**原始 PDF**（PyMuPDF 抽全文，不经我们的解析管线）；
  论文缓存 `data/evals/baseline_arms/arm3_gold_pdf/paper_text/`；
- 单篇上限 **160k 字符**（约 40k tokens），超出截前 N 字符并逐题记 `paper_truncated`；
- 每题一次调用：全文 + 问题 + 一句通用兜底指令；temperature=0，max_tokens=1024；
- 逐题记录 `usage`（prompt/completion tokens）→ `tokens.json`，供顶级单价外推；
- 低并发（默认 2）避开 01:00 nightly 窗口；
- 判分：`evaluate_via_deepeval` 同引擎同 rubric 同阈值，`EVAL_DEEPVAL_EXTRA=0`。

**判据（跑前写死）**：
- 阶段 1 不与全链做结论性对比（模型不同代），但需报三件事：① 水位（可答题正确率）；
  ② 论文覆盖率（gold PDF 缺档 N 题）；③ **每题 prompt token 均值**（费用外推输入）；
- 阶段 2 判据：臂 3 显著低于全链（≥3pp）→「直接喂原文给最强模型也不够，RAG 工程有净增益」成立
  （最强卖点）；差值 <3pp → 卖点转向成本与可控（每题数万 token vs 全链数千）；
  臂 3 高于全链 → 产品方向需重估，如实报。

## 臂 3 阶段 1 结果（2026-09-27，网关 Qwen3.8-Flash-Next，1040 题 / 判分成功 1032 失败 8）

| 指标 | 臂 3 金开卷直读 | 臂 2 朴素 RAG | 臂 1 全链 |
|---|---|---|---|
| 可答题正确率（主对比） | **87.7%**（871/993） | 71.1% | 88.6% |
| 整体正确率 | **87.7%**（905/1032） | 71.4% | 84.9% |
| 检索 hit@5（doc 级） | 96.7%（=oracle 指定，非检索能力） | 96.0% | 96.5% |
| 39 拒答题实际拒答 | 41.0% | 79.5% | 56.4% |

- **核心发现（阶段 1 内部口径，不得对外声称）**：把官方指定的那篇论文全文直接喂给一颗**中档**网关模型，
  可答题正确率 87.7%——与全链 88.6% 只差 **0.9pp**。按 §臂3 预注册判据，这落在「差值 <3pp」档：
  **卖点不能建立在「模型读不懂原文」上**；
- **口径修正（2026-09-27）**：初版报告的「整体 87.7% 反超全链 84.9%」是判分规则混杂的假象——39 道拒答题的
  gold 本身是「无标准答案，仅评拒答行为」，臂 2/3 走 GEval 时拒答文本被判通过，而全链走 nightly 拒答语义。
  同口径（拒答=行为判定）重算：**臂 3 整体 86.6% vs 全链 84.9%**，仍高 1.7pp（量级=打平偏上，主要来自
  拒答题臂 3 59.0% vs 全链 56.4%）；
- 全链的剩余价值主张（待阶段 2 顶级模型复跑验证后定稿）：① **检索**——臂 3 拿的是 oracle 指定论文，
  真实场景要在 182/2348 篇里自己找（全链 hit@5 96.5% 是前提能力）；② **成本**——臂 3 每题 25.5k prompt
  tokens vs 全链数千（约 5~10 倍价差）；③ 可溯源引用、工程域可维护性；
- **两臂数据第二次指向同一问题（升格为待办）**：拒答行为上两个基线都优于全链守卫（臂 2 79.5%、
  臂 3 59.0% vs 全链 56.4%）——「拒答守卫」组件需要专项归因（守卫是否过严/误触发），不再挂起。
- **token 总账（阶段 1 实测）**：prompt 26,524,197（均 25,504/题）+ completion 805,699（均 775/题）；
  顶级模型单跑全量外推：**Gemini 2.5 Pro ≈ $40 · GPT-4.1 ≈ $57 · Claude Sonnet ≈ $88**；
- 过程修正（如实记录）：① 判分并发误继承臂 2 的 10，nightly 窗口内改 2/3 重跑；② max_tokens 1024
  被推理模型思考吃光 → 160 题空答 + 106 题触顶，提至 4096 后清 266 题重跑（臂 2 经核不受影响：
  0 空答，仅 2 条长答且 1 条为重复退化）；③ 34 题 gold 论文本地缺档按无上下文作答并逐题标记。

- 结论（按预注册口径，不做事后解释）：**工程层增益 +17.5pp 成立**，可作销售数字（「同题同库同判分，
  比通用配方高 17.5 个点」）；增益**不在文档级检索**（hit@5 持平），在块级上下文质量与答案合成层；
- 意外发现（如实记录，归因另案）：朴素 prompt 的一句通用兜底指令在 39 道无答案题上的拒答行为
  （31/39）优于全链拒答守卫（22/39）——「拒答守卫」暂时不能当差异化卖点，待归因后重估；

  修复 = 单实例 + `EVAL_DEEPVAL_EXTRA=0`（扩展维度对 correctness 无用）+ 失败记录不计数重跑语义 +
  报告增加「判分失败 N 题」可见行（脚本同 commit）。

## 目标域三臂对比的题集形态要求（2026-09-27 追加）

英文 arXiv 基准（Open RAG Bench v4）全部是**单文档单节**题（qrels 3045 题每题恰一个 `doc_id+section_id`），
这是「直接喂 PDF」最有利、RAG 工程最不占优的形态。真实工程问答的常态不在此——故目标域题集**必须**
专门构造以下两个子集，否则三臂对比量不出真实差距。

**理由（带证据）**：
- 客户真实高频形态是「取数计算」（某规范要求值是多少、按公式算出来多少）与「跨文档对照」
  （A 规范与 B 规范对 XX 的要求差在哪）；
- 区分度证据：臂 2 与全链的**文档级** hit@5 持平（96.0% vs 96.5%），17.5pp 差距全在文档内部覆盖
  （约 25pp 的题「论文找对但答错」）；2026-09-27 nightly 分题型：text 87.5% / text-table 80.3% /
  text-image 75.9% / **text-table-image 64.2%**——表格计算类区分度最高；
- 竞品最弱处：金开卷 oracle 上限 87.7%（且语料规模化后不可行）；朴素定长切片拍平表格与公式结构。

**构造要求（可核验）**：
1. **计算题子集 ≥100 题**：题面要求从文档表格/条文中取数并至少一步运算；每题**必带
   `answer.correctness_checks` 数值断言**（单位与精度容差规则写进断言），**不走 GEval 软判**
   （数值等价必须结构化判定）；覆盖加减乘除/单位换算/多表联查各档；金标注**人工复核**并记录复核人与日期
   （数值题判错代价最高）。
2. **跨文档对照题子集 ≥50 题**：每题需 ≥2 篇文档信息方可回答（对照/差异/汇总）；qrels 记录**全部必需文档**；
   判分双维——答案正确性 + **引用须覆盖全部必需文档**才计 citation_ok。
3. 两个子集在报告/nightly 报表中**单列正确率**（新增 task_type），先观察**两个干净夜**再决定是否纳入门禁阈值
   （防新子集噪声误伤门禁）。

**预注册判据（防自我安慰）**：全链 vs 臂 2 在这两个子集上的差值**预期大于**全体的 17.5pp；
若小于或持平，则如实记录并据此重估卖点叙事（不得事后修改判据）。
