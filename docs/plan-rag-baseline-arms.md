## 指标与预注册判据

| 指标 | 臂 2 读法 | 对照（臂 1） |
|---|---|---|
| 可答题正确率（1001 题，主对比） | judge semantic_passed | **88.6%** |
| 整体正确率（1040 题） | 同上（臂 2 无守卫，拒答题按实际回答判） | 84.9% |
| 检索 hit@5（doc 级，qrels gold） | top-5 块去重后的论文集合是否含 gold 论文 | 96.5% |
| 拒答行为（39 题） | `is_refusal` 判定臂 2 是否作答（预期几乎全硬答） | 拒答正确率 56.4% |

**判据（跑前写死，跑后不回改解释）**：

- 可答题正确率差 **≥ 3pp** → 工程层增益成立，可作销售数字（「同题同库同判分，比通用配方高 X 个点」）；
- 差 **< 3pp** → 增益不显著，卖点转向「私有语料可控、引用可溯源、拒答守卫、工程域定制」，不宣称正确率领先；
- hit@5 差 ≥ 6.5pp（96.5 − 90）→ 检索层是增益主导；臂 2 hit@5 ≥ 93.5% → 检索层增益有限，增益主要在生成/守卫层；
- 39 题硬答率 > 80% → 「拒答守卫防跨文档幻觉」单独立为差异化卖点。

## 公平性纪律

1. 配方参数不做逐题调优；**100 题试点只看管道健康**（报错率、hit@5 水位、答案目检），不据此改配方；
2. 臂 2 喂的是原始 PDF 抽取文本，臂 1 吃的是我们解析管线产物——这个差异是**被测变量本身**（解析质量也是工程的一部分），如实呈现不遮掩；
3. 判分失败题按 nightly 同规则兜底（关键词断言），不人工改判；
4. 结果无论好坏都发布到本文件的结果段——**选择性报告 = 全部作废**。

## 臂 3 预注册（2026-09-27 追加，跑前写死）

**目的**：回答「把原文 PDF 直接给大模型，还要不要 RAG」——对销售与产品方向都最锋利的一问。

**两阶段口径（本文件同时声明两次跑的定位，避免结论混用）**：

| 阶段 | 模型 | 定位 |
|---|---|---|
| 阶段 1（本次，2026-09-27） | 网关注册的 **Qwen3.8-Flash-Next**（`/api/llm2`） | **只作内部水位 + 每题 token 计量**；非顶级模型，结论**不得对外声称** |
| 阶段 2（待用户提供顶级 key） | 顶级长上下文模型（Gemini 2.5 Pro 首选） | 正式臂 3，对外结论以此次为准 |

**配方（两阶段一致，仅换模型）**：
- 输入 = qrels 指定的该题 gold 论文**原始 PDF**（PyMuPDF 抽全文，不经我们的解析管线）；
  论文缓存 `data/evals/baseline_arms/arm3_gold_pdf/paper_text/`；
- 单篇上限 **160k 字符**（约 40k tokens），超出截前 N 字符并逐题记 `paper_truncated`；
- 每题一次调用：全文 + 问题 + 一句通用兜底指令；temperature=0，max_tokens=1024；
- 逐题记录 `usage`（prompt/completion tokens）→ `tokens.json`，供顶级单价外推；
- 低并发（默认 2）避开 01:00 nightly 窗口；
- 判分：`evaluate_via_deepeval` 同引擎同 rubric 同阈值，`EVAL_DEEPVAL_EXTRA=0`。

**判据（跑前写死）**：
- 阶段 1 不与全链做结论性对比（模型不同代），但需报三件事：① 水位（可答题正确率）；
  ② 论文覆盖率（gold PDF 缺档 N 题）；③ **每题 prompt token 均值**（费用外推输入）；
- 阶段 2 判据：臂 3 显著低于全链（≥3pp）→「直接喂原文给最强模型也不够，RAG 工程有净增益」成立
  （最强卖点）；差值 <3pp → 卖点转向成本与可控（每题数万 token vs 全链数千）；
  臂 3 高于全链 → 产品方向需重估，如实报。

## 结果（2026-09-26 全量，1040/1040 判分成功 0 失败）

| 指标 | 臂 2 朴素 RAG | 臂 1 全链 | 差值 | 预注册判据 | 判定 |
|---|---|---|---|---|---|
| 可答题正确率（主对比，1001 题） | **71.1%**（712/1001） | 88.6% | **−17.5pp** | ≥3pp = 工程增益成立 | ✅ 远超阈值 |
| 整体正确率（1040 题） | 71.4%（743/1040） | 84.9% | −13.5pp | — | 同向 |
| 检索 hit@5（doc 级，qrels） | 96.0%（998/1040） | 96.5% | −0.5pp | 差 <6.5pp = 检索层增益有限 | ✅ 触发：差距不在检索 |
| 拒答题硬答率（39 题） | 20.5%（8/39） | （全链拒答正确率 56.4%） | — | 硬答率 >80% = 守卫单列卖点 | ❌ 未触发：**朴素指令的拒答行为（79.5%）反而优于全链守卫（56.4%）** |

- 结论（按预注册口径，不做事后解释）：**工程层增益 +17.5pp 成立**，可作销售数字（「同题同库同判分，
  比通用配方高 17.5 个点」）；增益**不在文档级检索**（hit@5 持平），在块级上下文质量与答案合成层；
- 意外发现（如实记录，归因另案）：朴素 prompt 的一句通用兜底指令在 39 道无答案题上的拒答行为
  （31/39）优于全链拒答守卫（22/39）——「拒答守卫」暂时不能当差异化卖点，待归因后重估；
- 过程记录：首判因多进程叠罗汉致 84% 判分失败（28 并发打挂网关），已全部作废重判；
  修复 = 单实例 + `EVAL_DEEPVAL_EXTRA=0`（扩展维度对 correctness 无用）+ 失败记录不计数重跑语义 +
  报告增加「判分失败 N 题」可见行（脚本同 commit）。
